# Prompt Studio 界面设计系统

## 1. 产品方向与使用情境

### 使用者

主要使用者是需要反复检查提示词效果、比较不同模型表现的产品经理、模型工程人员和 AI 应用设计人员。他们通常已经准备好一套系统提示词，需要快速改变模型、用户提示词或生成参数，并直接观察输出差异。

### 核心任务

在同一套系统提示词下，同时运行 1–3 个相互独立的模型评测栏，并横向比较模型响应、耗时和 Token 数据。系统提示词是共享控制变量；用户提示词、模型和生成参数是每栏独立的实验条件。

### 体验感受

界面应像一张安静、严谨、可重复操作的实验台：信息密度适中，控制区紧凑，输出区易读，不使用装饰性渐变和无意义色彩。使用者应能立即分辨共享条件、独立条件、运行状态与输出结果。

### 产品领域词汇

- 共享系统提示词：所有评测栏共同使用的角色、边界和输出要求。
- 独立用户提示词：只发送给当前评测栏所选模型的输入。
- 评测栏：一组独立的模型、提示词、参数、运行状态和响应结果。
- 控制变量：模型对比时保持一致的共享系统提示词。
- 生成参数：温度和最大输出 Token 等影响模型响应的参数。
- 模型响应：模型生成的正文结果。
- 运行指标：耗时、输入 Token 和输出 Token。
- 并排评测：让多个模型栏保持相邻，支持直接横向比较。

## 2. 视觉方向

### 色彩世界

色彩来自实验台、研究记录和仪器状态灯：

- 实验台画布：冷静的浅灰 `#f3f5f7`。
- 记录纸与仪器面板：白色 `#ffffff`。
- 输入槽：略深于表面的灰色 `#f1f3f5`，表达可输入的内凹区域。
- 墨色：深蓝黑 `#1d2430`，用于主要文字和品牌标记。
- 仪器蓝：`#315eea`，只用于主要动作、焦点和正在运行状态。
- 完成绿：`#178b62`，只表示成功或完成。
- 错误红：`#c23b4a`，只表示错误和危险删除动作。
- 提醒琥珀：`#a36a0b`，预留给警告和需要注意但未失败的状态。

色彩遵循约 60/30/10 的分配：大部分空间使用画布和白色表面，次要区域使用灰色层级，蓝色只占少量并明确传达动作或状态。

### 标志性元素

每个评测栏顶部具有一条 3px 高的“模型状态轨道”：

- 等待运行：中性灰。
- 正在运行：蓝色移动信号。
- 运行完成：完成绿。
- 运行失败：错误红。

状态轨道必须与栏内的状态圆点、按钮状态和结果内容保持一致。它是模型评测场景专属的识别元素，不替换文字状态，而是用于快速扫视多个评测栏。

### 明确拒绝的默认表达

- 不使用普通后台常见的彩色卡片矩阵；改用连续的并排实验栏。
- 不把左侧区域做成深色导航栏；共享提示词与模型响应是同级实验内容，使用相同白色体系和轻边界分隔。
- 不使用大面积渐变、霓虹光和装饰性数据图表；颜色只传达动作与状态。
- 不让所有文本使用同一字号和灰度；通过字重、颜色和间距建立层级。
- 不使用剧烈阴影制造浮层；评测工具需要稳定、平整和可长时间阅读。

## 3. 布局与层级

### 页面结构

- 顶部工具栏：桌面端高度 68px，负责产品识别、添加模型和运行全部模型。
- 左侧共享条件区：桌面端宽度 344px；在宽度低于 1050px 时收窄至 300px。
- 右侧并排评测区：占据剩余宽度，包含 1–3 个评测栏。
- 桌面三栏：每栏最小宽度 276px，空间允许时等宽扩展。
- 两栏及以下：栏位最小宽度 280px，同时显示添加模型占位入口。
- 窄屏：共享条件区移到评测区上方；评测栏保持至少 286px 或约 86vw 的可读宽度，通过横向滚动比较，不把三栏压缩成不可读的窄卡片。

### 视觉焦点

模型响应是每个评测栏的核心内容。层级顺序为：

1. 模型响应及其完成状态。
2. 当前模型名称和用户提示词。
3. 运行当前模型与运行全部模型的动作。
4. 模型参数和运行指标。
5. 辅助说明、字符数、栏位数量等元数据。

共享系统提示词始终可见并占据左侧主要面积，因为它是所有评测栏共同的控制变量，但其视觉对比不应压过右侧的模型输出。

## 4. 设计令牌

### 颜色令牌

```css
--lab-canvas: #f3f5f7;
--lab-surface: #ffffff;
--lab-inset: #f7f8fa;
--lab-control: #f1f3f5;
--lab-ink: #1d2430;
--lab-secondary: #596476;
--lab-tertiary: #7c8797;
--lab-muted: #a6aebb;
--lab-border: rgba(25, 35, 50, 0.1);
--lab-border-strong: rgba(25, 35, 50, 0.17);
--lab-blue: #315eea;
--lab-blue-hover: #244dcc;
--lab-blue-soft: #edf1ff;
--lab-green: #178b62;
--lab-green-soft: #e8f6f0;
--lab-red: #c23b4a;
--lab-red-soft: #fcedef;
--lab-amber: #a36a0b;
```

### 文字层级

- 主文字 `--lab-ink`：标题、模型名称、重要结果和关键数值。
- 次文字 `--lab-secondary`：正文、字段标签和主要辅助内容。
- 三级文字 `--lab-tertiary`：说明、参数摘要和非关键操作。
- 弱化文字 `--lab-muted`：占位、禁用状态和低优先级元数据。

### 字体

字体栈：`"Avenir Next", "PingFang SC", "Microsoft YaHei", sans-serif`。

- 页面标题：22px / 650，字间距 `-0.025em`。
- 区域标题：18px / 650。
- 品牌和模型名称：13–15px / 650。
- 正文和输入内容：12–13px / 400，行高 19–22px。
- 字段标签：11px / 650。
- 元数据与眉题：9–10px / 600–650，眉题使用约 `0.09em` 字间距。
- 动态数字使用 `font-variant-numeric: tabular-nums`，避免耗时、Token 和进度数字跳动。

### 间距

基础单位为 4px，只使用 4px 的整数倍作为主要间距：

- 微间距：4px、8px。
- 控件内部间距：8px、12px、16px。
- 卡片或栏内分组：12px、16px、20px。
- 页面区块：24px、28px、32px。

控件密度采用工作台级紧凑布局：评测栏内边距为 16px；左侧共享区为 24px；右侧评测区桌面端为左右 24px、顶部 28px。

### 圆角

```css
--lab-radius-sm: 7px;
--lab-radius-md: 10px;
--lab-radius-lg: 14px;
```

- 小圆角：按钮、选择器、参数区和指标条。
- 中圆角：文本输入区、提示说明和结果内容区。
- 大圆角：完整评测栏和添加评测栏入口。

嵌套元素应保持同心圆角关系：外层圆角应等于或大于内层圆角加周边内距，不在小按钮上使用大圆角。

### 深度策略

主要使用“轻边界 + 极浅阴影”的单一策略：

- 页面区域依靠白色与浅灰色表面变化建立层级。
- 输入框使用比周围表面更深的背景，表达内凹和可编辑性。
- 评测栏使用 `1px` 低透明边界、`1px` 轻阴影和极弱远距阴影。
- 分隔线使用 `--lab-border`，正常浏览时不应成为视觉焦点。
- 不混用厚边框、强投影、玻璃高光和多种海拔体系。

## 5. 可复用组件规范

### 顶部主要按钮

- 高度：至少 40px。
- 水平内边距：15px。
- 圆角：7px。
- 字体：13px / 600。
- 图标与文字间距：8px。
- 默认背景：`--lab-blue`；悬停：`--lab-blue-hover`。
- 按下反馈：`scale(0.97)`，持续约 120ms。
- 禁用时降低透明度，并保持不可点击光标。

### 顶部次要按钮

尺寸与主要按钮一致，使用白色表面、低透明边界和极浅阴影。悬停时只轻微加深背景和边界，不与主要动作竞争。

### 图标按钮

- 点击区域：40 × 40px。
- 圆角：7px。
- 默认使用三级文字色。
- 删除动作悬停时使用错误红与淡红背景。
- 必须提供可访问名称和原生 `button` 语义。

### 评测栏

- 外层圆角：14px。
- 标题区最小高度：76px。
- 标题区内边距：顶部与左右 14px、底部 13px。
- 内容区内边距：16px。
- 顶部保留 3px 模型状态轨道。
- 栏号使用两位数显示，例如 `01`、`02`、`03`。
- 同一页面的全部评测栏必须等宽并顶部对齐。

### 用户提示词输入框

- 高度：116px。
- 内边距：12px。
- 字体：12px，行高 19px。
- 默认背景：`--lab-control`。
- 聚焦时切换为白色表面，并使用半透明蓝色边界和蓝色焦点环。
- 每栏用户提示词必须独立保存和更新，不与其他评测栏联动。

### 共享系统提示词输入框

- 桌面端占据左侧剩余主要空间，最小高度 280px。
- 窄屏最小高度 190px。
- 内边距：顶部与左右 16px，底部 40px，为字符计数预留空间。
- 字体：13px，行高 22px。
- 输入内容变化必须同步影响全部评测栏的下一次运行。

### 模型参数区

- 使用原生 `details` 和 `summary` 语义。
- 折叠状态高度至少 40px。
- 默认只显示“模型参数”和简洁摘要，例如 `T 0.7 · 2048`。
- 展开后显示温度滑块及最大输出 Token 选择器。
- 参数属于当前评测栏，不跨栏同步。

### 单栏运行按钮

- 宽度：评测栏内容区全宽。
- 最小高度：40px。
- 默认使用淡蓝背景和蓝色文字。
- 悬停时变为蓝色背景和白色文字。
- 运行中显示旋转状态图标和“生成响应中”，并暂时禁用重复触发。

### 结果内容区

- 最小高度：270px，保证评测栏在无内容时仍保持稳定布局。
- 默认背景：`--lab-inset`。
- 必须具备等待、运行中、完成和错误四种状态。
- 使用 `aria-live="polite"` 播报异步结果变化。
- 运行中设置 `aria-busy="true"`。
- 标题、编号行动项、假设与边界应具有明确文本层级，不能只输出一整块无结构正文。

### 运行指标条

- 三等分展示耗时、输入 Token 和输出 Token。
- 使用轻边界分隔，不使用三个独立彩色徽章。
- 数值使用 10px / 650 和等宽数字；标签使用 8px 三级文字色。

### 供应商连接状态

- 顶部工具栏显示“已连接供应商数 / 全部供应商数”，不得再使用“本地演示”或可能误导为真实调用的模糊状态。
- 左侧共享条件区显示真实 API 模式说明、已连接数量和四个供应商状态轨道。
- 已连接使用完成绿；未配置使用提醒琥珀，不能把未配置误判为运行错误。
- 未配置供应商的模型名称必须追加“未配置”，对应单栏按钮显示“需要 API Key”并禁用。
- 当至少一个当前栏位使用已连接模型时，“运行全部”才可用；运行全部只调用已连接的栏位。

### 添加评测栏入口

- 使用虚线轻边界和半透明白色表面。
- 桌面端最小高度 190px。
- 只在评测栏少于 3 个时出现。
- 达到 3 栏后，顶部“添加模型”按钮同步禁用。

## 6. 状态与交互

### 评测状态定义

- `idle`：尚未运行，显示中性灰状态轨道和等待提示。
- `running`：模型正在生成响应，显示蓝色移动状态轨道、加载骨架和旋转图标。
- `done`：响应生成完成，显示完成绿轨道、结构化结果、复制入口和运行指标。
- `error`：用户提示词为空或模型调用失败，显示错误红轨道和明确修正提示。

### 动效

- 普通悬停和焦点反馈：约 150–160ms。
- 按钮按下反馈：约 120ms。
- 所有交互动效使用明确的 `transform`、`opacity`、`background-color`、`border-color` 或 `box-shadow` 属性，不使用 `transition: all`。
- 进入与交互使用 `cubic-bezier(0.23, 1, 0.32, 1)`。
- 状态轨道和加载骨架可循环运动，但必须遵循 `prefers-reduced-motion`；用户请求减少动画时取消位移动画。

### 可访问性

- 所有操作使用原生按钮、选择器、文本框、滑块和折叠元素。
- 交互元素必须具备默认、悬停、按下、键盘焦点和禁用状态。
- 主要按钮与图标按钮点击区域不得小于 40px；新增控件优先达到 44px。
- 仅有图标的按钮必须提供 `aria-label`，同时可以提供原生 `title` 作为鼠标提示。
- 颜色不能作为唯一状态表达，必须同时提供状态文字、图标或内容变化。
- 窄屏不能通过过度压缩字号和栏宽解决空间问题，应保留可读宽度并允许横向浏览。

## 7. 后续模块复用规则

- 新增评测相关页面时优先复用 `--lab-*` 语义令牌，不新增随机十六进制颜色。
- 同一种按钮、输入框、评测栏或指标条出现第二次时，应抽取为共享组件，而不是复制整段样式。
- 新状态色必须具有清楚的语义定义；装饰性颜色不能进入设计令牌。
- 新页面仍以模型响应或评测结论为焦点，设置、参数与元数据必须降级展示。
- 如果后续增加自动评分，评分结果应作为模型响应之后的独立分析层，不覆盖原始模型输出，也不能让评分色彩破坏单一蓝色动作体系。
- 真实模型调用必须通过本地服务端适配层完成。供应商 API 密钥只从 `.env.local` 读取，不得进入浏览器端、提示词、日志响应或版本控制。
- 模型目录必须使用厂商真实模型 ID，并向界面返回供应商、模型名称和可用状态；不得添加模拟响应作为真实调用的静默后备方案。
- 上游调用保留 120 秒超时，错误状态显示厂商返回的可操作信息；后续可继续增加取消和重试反馈。
- 修改本文件中的设计规则时，必须同步检查 `src/styles.css` 和实际组件状态，确保文档与实现一致。

## 8. 统一工作站模块系统

### 顶部模块导航

- 产品名称统一为“模型工作站 / Model Lab”。
- 顶部导航包含“提示词工程”“模型评测”“模型测试”，三个入口始终可见并保持固定顺序。
- 当前模块使用淡蓝背景和仪器蓝文字；非当前模块使用三级文字色，悬停时只提高文字对比和表面亮度。
- 模块导航使用原生按钮和 `nav` 语义，支持键盘焦点。
- 桌面端模块导航位于品牌与上下文动作之间；窄屏端独立占据第二行，并允许横向浏览。
- 右侧上下文动作随当前模块变化：提示词工程显示“发送到评测”；模型评测显示“添加模型”和“运行全部”；模型测试显示“添加用例”和“运行测试”。

### 跨模块共享状态

- 系统提示词只有一个状态源，提示词工程、模型评测和模型测试同时读取和修改该值。
- 模型目录和供应商连接状态只有一个状态源，通过 `/api/models` 获取。
- 提示词工程编译出的用户提示词可以覆盖模型评测第一栏，也可以追加为模型测试用例；切换模块不得清空已有内容。
- 模型评测和模型测试共用 `/api/evaluate` 请求函数，不能复制或创建独立的供应商调用逻辑。

### 提示词工程视图

- 页面焦点是带变量的用户提示词模板，使用淡蓝边界强调；共享系统提示词保持同级但不抢占焦点。
- 桌面端采用编辑器区与预览区双栏结构：左侧宽约 1.45 份，右侧宽约 0.75 份。
- 模板变量使用 `{{变量名}}` 语法，通过正则提取唯一变量名并自动生成输入字段。
- 实时编译结果使用等宽字体，保留换行和空白，以便检查最终发送内容。
- “加入测试”和“发送到评测”放在编译结果底部，形成从编写到验证的明确下一步。
- 窄屏端所有区域按系统提示词、提示词模板、变量、编译结果的顺序垂直排列。

### 模型测试视图

- 页面焦点是测试用例列表和通过率汇总，不使用模型评测卡片结构。
- 顶部汇总同时显示用例总数、通过、失败和错误；动态数字使用等宽数字。
- 每条用例包含两位栏号、可编辑名称、用户提示词、可选预期包含文本、状态、删除和单条运行操作。
- 每条用例左侧保留 3px 状态轨道：待运行为灰色、运行中为蓝色、通过为绿色、失败和错误为红色。
- 测试状态定义为 `idle`、`running`、`passed`、`failed`、`error`，每种状态同时使用文字和颜色表达。
- “预期包含文本”为空时，真实 API 成功返回非空结果即视为通过；填写后，响应必须包含目标文本才通过。
- 模型响应存放在原用例内部的原生 `details` 中；失败和错误默认展开，通过结果默认折叠。
- 所有测试用例共用当前系统提示词和当前测试模型；测试默认温度为 0.2、最大输出 Token 为 2048，以降低随机性并提高回归比较稳定性。
